# 北极熊桌宠项目期末答辩五大模块讲解稿

本文档用于期末答辩代码讲解。整体讲解顺序建议固定为：

```text
先讲模块作用 -> 再现场演示功能 -> 最后打开代码讲逻辑
```

项目当前按五大模块组织：

1. `core` 主控模块
2. `pet` 桌宠表现模块
3. `data` 数据与成长模块
4. `features` 功能页面模块
5. `services` 外部服务模块

建议答辩时先用 30 秒讲总架构：

> 这个项目是一个基于 Python + PySide6 的北极熊桌面宠物系统。代码被划分为五个核心模块：`core` 负责应用主控和调度，`pet` 负责桌宠动画与桌面交互，`data` 负责状态、等级、任务和本地存档，`features` 负责控制面板中的功能页面，`services` 负责大模型聊天和课程表 OCR 等外部能力。这样拆分之后，界面、动画、数据和服务逻辑比较清楚，也方便后续维护。

## 一、core 主控模块

路径：

```text
src/core/app.py
main.py
```

核心类：

```text
PolarBearPetApp
```

### 1. 模块作用

答辩可以这样讲：

> `core` 模块是整个项目的主控中心，相当于系统的大脑。它负责启动程序、创建主控制面板、创建北极熊桌宠窗口，并把数据模块、功能页面模块、桌宠动画模块和外部服务模块连接起来。

它主要完成几件事：

- 启动 PySide6 应用程序。
- 创建主控制面板窗口。
- 初始化北极熊桌宠悬浮窗。
- 加载左侧导航和各个功能页面。
- 管理系统托盘。
- 注册快捷键，例如显示/隐藏桌宠、右下角圆圈待机。
- 接收桌宠交互事件，并分发到数据层或功能层。

### 2. 演示方式

现场演示建议：

1. 运行项目：

```bash
python main.py
```

2. 展示控制面板：

- 说明左侧导航栏由主控模块统一创建。
- 点击不同页面，例如“宠物状态”“课程提醒”“聊天互动”“系统设置”。

3. 展示快捷键和托盘：

- 按 `Ctrl+Alt+B` 显示或隐藏北极熊。
- 按 `Ctrl+Alt+M` 让北极熊进入右下角圆圈待机，再按一次召回。
- 右下角系统托盘菜单可以快速控制桌宠。

可以边演示边说：

> 大家现在看到的这些页面切换、桌宠显示隐藏、快捷键和托盘功能，都是 `core` 模块在做统一调度。它本身不直接处理具体业务，而是负责把不同模块组织起来。

### 3. 代码逻辑讲解

打开文件：

```text
main.py
src/core/app.py
```

讲解入口：

```text
main.py
```

讲解思路：

> `main.py` 是程序入口，它创建 QApplication，然后实例化 `PolarBearPetApp`，最后进入 Qt 的事件循环。这样桌宠窗口和控制面板就都能响应鼠标、快捷键、定时器等事件。

重点讲 `src/core/app.py`：

```text
PolarBearPetApp
```

可以按这几层讲：

1. 初始化阶段

- 创建数据存储对象 `PetDataStore`。
- 创建桌宠窗口 `PolarBearPetWindow`。
- 连接桌宠的交互信号。
- 构建主界面。
- 构建托盘菜单。
- 注册快捷键。

2. 页面调度逻辑

主控模块通过 `QStackedWidget` 管理不同页面：

- 背包页面来自 `src/features/backpack.py`
- 聊天页面来自 `src/features/chat.py`
- 成长页面来自 `src/features/growth.py`
- 课程提醒页面来自 `src/features/notification.py`
- 设置页面来自 `src/features/settings.py`

答辩可以这样说：

> 页面不是全部写死在一个文件里，而是由 `core` 统一装配，各个页面实现自己的功能。这样主窗口负责调度，功能页面负责业务。

3. 桌宠控制逻辑

重点讲这几个能力：

- `show_pet_window()`：显示桌宠。
- `hide_pet_window()`：隐藏桌宠。
- `toggle_pet_window()`：显示/隐藏切换。
- `toggle_pet_corner_standby()`：立即进入或退出右下角圆圈待机。
- `_play_pet_action()`：触发桌宠动作。

答辩可以这样说：

> 比如用户点击控制面板的“挥手”按钮，主控模块不会自己画动画，而是调用 `pet` 模块中的 `PolarBearPetWindow.play_action()`，让桌宠窗口播放对应动作。

4. 信号分发逻辑

桌宠窗口会发出交互信号，主控模块负责处理：

- 点击桌宠。
- 拖拽桌宠。
- 选择气泡菜单。
- 进入角落隐藏。
- 从角落返回。

讲解句：

> 这里使用 Qt 的信号槽机制，把桌宠窗口和主控窗口解耦。桌宠只负责告诉主控“发生了什么”，主控再决定要更新数据、播放动作还是显示气泡。

## 二、pet 桌宠表现模块

路径：

```text
src/pet/window.py
```

核心类：

```text
PolarBearPetWindow
FrameAction
```

### 1. 模块作用

答辩可以这样讲：

> `pet` 模块负责桌面上那只北极熊本身，包括它的透明悬浮窗口、序列帧动画、点击和拖拽交互、气泡显示、贴边吸附、右下角圆圈待机等。它是用户最直观看到的部分。

它主要完成：

- 加载北极熊 PNG 序列帧。
- 播放待机、挥手、跳跃、走路、睡觉等动作。
- 处理鼠标点击、双击、拖拽。
- 控制桌宠在屏幕上的移动。
- 显示聊天气泡和功能选择气泡。
- 支持贴边和右下角圆圈待机。
- 优化动作结束时的抖动和瞬移问题。

### 2. 演示方式

现场演示建议：

1. 展示北极熊待机：

- 让北极熊在桌面上显示。
- 说明待机状态下它会眨眼或轻微变化。

2. 展示动作：

- 在控制面板点击“挥手”“跳跃”“左走”“右走”“睡觉”。
- 观察动作播放结束后平滑回到待机。

3. 展示桌面交互：

- 拖拽北极熊移动。
- 点击北极熊弹出功能选择。
- 右键打开菜单。
- 让它贴边或进入右下角圆圈待机。

讲解句：

> 这部分的重点不是简单移动一张图片，而是通过 PNG 序列帧播放真实动作。每个动作都有多帧图片，定时器按照帧率刷新，从而让北极熊看起来是在真实运动。

### 3. 代码逻辑讲解

打开文件：

```text
src/pet/window.py
```

核心数据结构：

```text
FrameAction
```

讲解：

> `FrameAction` 用来描述一个动作，包括动作名、显示名称、帧列表、帧间隔、是否循环、是否需要移动窗口等。比如走路动作会有移动量，睡觉动作可以循环，挥手动作播放完后回到待机。

核心窗口类：

```text
PolarBearPetWindow
```

可以从以下逻辑讲：

1. 动画资源加载

`PolarBearPetWindow` 初始化时会定位素材目录：

```text
assets/polar_bear/role/PolarBear/action/
```

然后根据动作配置加载不同 PNG 序列帧。

答辩可以这样说：

> 每个动作不是一张图，而是一组连续 PNG 帧。程序启动时读取动作配置，把这些图片加载成 `QPixmap`，再按当前缩放比例进行缓存。

2. 定时器驱动动画

桌宠窗口内部有定时器，每隔很短时间触发一次 `_tick()`：

- 计算距离上一帧过去了多久。
- 判断是否该切换到下一帧。
- 如果动作播放完，就切换到下一个动作。
- 如果当前是待机，就根据计时触发随机动作或隐藏。

讲解句：

> 动画不是用视频播放器做的，而是由 Qt 定时器驱动，每次刷新时切换一张 PNG 帧，这样更容易和桌面交互、窗口移动、透明背景结合。

3. 动作切换逻辑

重点讲：

- `play_action()`：播放指定动作。
- `_current_frame()`：取得当前应该绘制的帧。
- `_start_return_transition()`：动作结束后回到待机的过渡。

可以说：

> 比如点击“挥手”时，主控模块调用 `play_action("wave")`。窗口会把当前动作切换成挥手，从第几帧开始、是否循环、下一步回到什么动作，都由 `FrameAction` 控制。

4. 绘制逻辑

桌宠窗口使用 `paintEvent()` 绘制：

- 清空透明背景。
- 绘制阴影。
- 绘制当前帧。
- 如果有气泡，再绘制气泡。
- 如果在圆圈待机模式，则绘制圆形小图标。

讲解句：

> 由于窗口本身是透明无边框的，所以看起来像北极熊直接站在桌面上。实际是 Qt 在透明窗口上绘制当前动画帧。

5. 鼠标交互逻辑

可以讲这些事件：

- `mousePressEvent()`：记录点击位置。
- `mouseMoveEvent()`：拖拽时移动窗口。
- `mouseReleaseEvent()`：判断是点击、拖拽结束还是选择气泡功能。
- `mouseDoubleClickEvent()`：触发双击动作。

讲解句：

> 这里把点击和拖拽区分开，防止用户只是拖动北极熊时误触发动作。拖拽结束后还会更新状态和日志。

6. 防抖和稳定性优化

可以重点讲：

> 项目中曾经遇到动作结束时抖动和瞬移的问题。现在的处理是：非循环动作结束后固定在最后一帧，不再错误地绕回第 0 帧；同时取消了逐帧移动窗口来修正姿态偏移的逻辑，避免动作结束时窗口剧烈抖动。

这能体现你对实际问题的优化。

## 三、data 数据与成长模块

路径：

```text
src/data/store.py
```

核心类：

```text
PetDataStore
```

### 1. 模块作用

答辩可以这样讲：

> `data` 模块负责项目所有核心数据，包括北极熊的饱食度、心情、体力、好感度、等级、经验、金币、背包、每日任务、课程提醒和操作日志。它还负责把这些数据保存到本地 JSON 文件中。

主要能力：

- 管理宠物状态。
- 管理等级和好感度机制。
- 管理金币和背包。
- 管理每日任务。
- 管理课程提醒。
- 记录操作日志。
- 读写 `data/save.json`。

### 2. 演示方式

现场演示建议：

1. 打开控制面板首页：

- 展示饱食度、心情、体力、好感度、金币、等级。

2. 做一次交互：

- 点击喂食。
- 观察饱食度或心情变化。
- 打开日志，展示系统记录。

3. 展示成长模块：

- 打开“成长等级”页面。
- 展示等级、经验、好感度阶段、每日任务。

4. 展示存档：

- 打开 `data/save.json`。
- 说明数据会本地持久化保存。

讲解句：

> 这里可以看到，界面上的数字不是写死的，而是由 `data` 模块统一计算和保存。用户重启程序后，这些数据仍然可以恢复。

### 3. 代码逻辑讲解

打开文件：

```text
src/data/store.py
```

核心类：

```text
PetDataStore
```

可以这样讲：

1. 默认数据结构

文件中定义了默认数据，包括：

- `stats`：饱食度、心情、体力、金币、好感度等。
- `inventory`：背包物品数量。
- `tasks`：每日任务完成情况。
- `settings`：透明度、快捷键、置顶、AI 配置等设置。
- `courses`：课程提醒数据。
- `logs`：系统日志。
- `growth`：成长和好感度数据。

讲解句：

> 这些默认值相当于第一次启动项目时的初始存档。如果本地没有 `save.json`，程序就会用默认数据创建一个新的存档。

2. 本地存档逻辑

`PetDataStore` 负责：

- 启动时读取 JSON。
- 数据变化后更新内存状态。
- 调用 `save()` 写回本地文件。
- 支持导入导出存档。

讲解句：

> 我没有使用数据库，而是使用 JSON 存档。因为桌宠属于轻量级桌面应用，JSON 更简单直观，答辩时也方便展示数据结构。

3. 状态变化逻辑

例如：

- 喂食会增加饱食度。
- 休息会恢复体力。
- 互动可能影响心情。
- 完成任务会获得少量经验或金币。
- 时间流逝会造成状态自然下降。

讲解句：

> 所有状态变化都集中在 `PetDataStore`，这样不会出现某个页面自己乱改数据的问题。界面只负责调用数据层提供的方法。

4. 等级和奖励机制

可以讲：

> 等级系统不是简单点击就升级，而是通过经验值、每日任务和好感度上限来控制成长节奏。这样可以避免用户一直点击北极熊就快速刷满好感度。

可重点说明：

- 等级越高，升级需要的经验越多。
- 好感度有阶段和上限。
- 每日任务奖励有限。
- 金币获取更困难，提升养成深度。

5. 信号刷新机制

`PetDataStore` 继承自 `QObject`，可以发出数据变化信号。

讲解句：

> 数据更新后会通过信号通知界面刷新，避免界面一直手动轮询数据。这是 Qt 项目中比较常见的事件驱动写法。

### 1. 模块作用

答辩可以这样讲：

> `features` 模块负责控制面板里用户能看到和操作的功能页面。每个页面单独写成一个类，比如背包页面、聊天页面、成长页面、课程提醒页面和系统设置页面。这样每个功能相对独立，代码不会全部堆在主窗口里。

### 3. 代码逻辑讲解

打开目录：

```text
src/features/
```

可以按页面讲：

1. `backpack.py`

讲解重点：

- 从 `data` 模块读取物品目录和库存。
- 每个物品生成一张卡片。
- 点击购买或使用时调用 `PetDataStore`。
- 更新状态后刷新界面。

讲解句：

> 背包页面本身不直接修改 JSON 文件，而是调用数据层的购买、投喂和使用方法。这样页面只负责展示和交互，数据规则集中在 `data` 模块。

2. `growth.py`

讲解重点：

- 读取等级、经验、好感度信息。
- 展示成长进度和任务。
- 让用户看到下一等级目标。

讲解句：

> 成长页面主要是把数据层的等级和好感度机制可视化，让用户知道现在处于什么阶段，以及还差多少经验。

3. `interaction.py`

讲解重点：

- 页面按钮对应动作名。
- 点击按钮后调用主控传入的动作函数。
- 主控再调用 `pet` 模块播放动画。

讲解句：

> 这里体现了模块之间的解耦：页面不直接操作动画细节，只把“我要播放哪个动作”告诉主控。

4. `chat.py`

讲解重点：

- 显示聊天记录。
- 接收用户输入。
- 调用 `services` 中的大模型客户端。
- 把回复同步到聊天页面和桌宠气泡。

讲解句：

> 聊天页面主要负责输入输出界面，大模型请求的细节放在 `services` 模块中。

5. `notification.py`

讲解重点：

- 管理课程提醒。
- 支持手动输入课程。
- 支持通过 OCR 识别课表图片。
- 把识别出的课程写入数据层。

讲解句：

> 课程提醒页面把 OCR 服务识别出来的文本转换为结构化课程信息，再交给数据层保存。

6. `settings.py`

讲解重点：

- 修改桌宠大小、透明度、置顶。
- 修改快捷键。
- 配置大模型。
- 导入导出存档。

讲解句：

> 设置页是系统配置入口，很多设置项最终会写入 `data/save.json`，下次启动仍然生效。

## 五、services 外部服务模块

src/services/

核心能力：

LLMClient
recognize_timetable_image()

### 1. 模块作用

答辩可以这样讲：

> `services` 模块负责项目中比较独立的外部能力，比如大模型聊天和课程表 OCR 识别。这样做的好处是，界面页面不用关心具体 API 请求和 OCR 解析细节，只要调用服务模块提供的方法即可。

主要包括：

- 大模型聊天服务。
- OpenAI/DeepSeek/GLM 等模型配置。
- 课程表图片识别。
- OCR 文本清洗。
- 课程文本解析。

### 2. 演示方式

现场演示建议：

1. 大模型聊天：

- 打开“聊天互动”页面。
- 输入一句问题。
- 展示北极熊回复。
- 如果没有 API Key，可以展示系统设置中的模型配置入口。

2. 课程表识别：

- 打开“课程提醒”页面。
- 展示课表图片识别入口。
- 如果环境没有 OCR，也可以演示“识别文字粘贴后解析”。
- 展示解析后的课程导入到提醒列表。

讲解句：

> 这两个功能都不是写在页面里，而是封装在 `services` 模块中。页面只负责调用服务，服务负责处理外部能力。

### 3. 代码逻辑讲解

打开文件：

```text
src/services/llm_client.py
```

大模型逻辑可以这样讲：

1. 配置标准化

`normalize_llm_config()` 会整理模型配置：

- 是否启用大模型。
- 当前服务商。
- API 地址。
- 模型名称。
- API Key。

2. 统一客户端

`LLMClient` 封装请求逻辑：

- 根据配置选择服务商。
- 组装请求消息。
- 发送 HTTP 请求。
- 解析模型回复。

3. 桌宠人格提示词

`build_pet_system_prompt()` 会生成北极熊的人设提示词。

讲解句：

> 这样可以让北极熊不是普通机器人，而是带有桌宠身份、状态信息和陪伴风格的回复。

打开文件：

```text
src/services/course_ocr.py
```

OCR 逻辑可以这样讲：

1. 环境检测

`detect_ocr_status()` 判断电脑是否具备 OCR 能力，比如 Tesseract 或 Windows OCR。

2. 图片识别

`recognize_timetable_image(image_path)` 负责识别课程表图片：

- 读取图片。
- 尝试 OCR。
- 清洗识别文本。
- 尝试按课程表结构解析。

3. 文本解析

`parse_timetable_text(text)` 负责把识别到的文字解析成课程数据：

- 提取星期。
- 提取时间。
- 提取课程名。
- 提取地点。
- 去重和格式化。

讲解句：

> OCR 识别出来的结果通常比较乱，所以这里还做了文本清洗、课程名判断、地点判断和去重处理，让导入课程表更准确。

## 六、完整答辩演示路线建议

建议按下面顺序演示，比较顺：

1. 启动项目

```bash
python main.py
```

讲：

> 程序入口在 `main.py`，主控类是 `src/core/app.py` 中的 `PolarBearPetApp`。

2. 展示桌宠

讲：

> 桌宠表现逻辑在 `src/pet/window.py`，通过 PNG 序列帧播放动作。

3. 展示控制面板页面

讲：

> 控制面板页面拆在 `src/features/` 中，每个页面对应一个功能模块。

4. 演示状态变化

讲：

> 状态、等级、金币、好感度和存档逻辑都在 `src/data/store.py`。

5. 演示聊天或课程识别

讲：

> 大模型聊天和课表识别属于外部能力，统一放在 `src/services/`。

## 七、答辩时可以用的总结话术

最后可以这样收尾：

> 这个项目最开始功能比较集中，后期为了方便维护和答辩展示，我把代码整理成了五个模块。`core` 负责主控调度，`pet` 负责桌宠动画和桌面交互，`data` 负责状态成长和存档，`features` 负责控制面板的业务页面，`services` 负责 AI 和 OCR 等外部能力。这样拆分后，每个模块的职责更明确，后续如果要增加新动作、新页面或新服务，也可以在对应模块中扩展，不会影响整个项目结构。
