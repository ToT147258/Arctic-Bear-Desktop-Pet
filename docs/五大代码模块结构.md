# 北极熊桌宠项目五大代码模块结构

为了便于最终答辩说明，项目源码已经按职责拆分为五个主要模块包。每个模块只负责一类核心能力，主程序通过清晰的导入关系把它们组合起来。

## 1. core 主控模块

路径：`src/core/`

职责：
- 应用主窗口与控制面板入口
- 系统托盘、全局快捷键、页面切换
- 桌宠窗口与各功能页之间的调度

代表文件：
- `src/core/app.py`

答辩讲法：
`core` 是项目的“大脑”，负责启动应用、组织界面、连接桌宠表现层、数据层和功能页面。

## 2. pet 桌宠表现模块

路径：`src/pet/`

职责：
- 北极熊悬浮窗绘制
- PNG 序列帧动画播放
- 拖拽、点击、贴边、隐藏圆点、动作切换
- 气泡和交互菜单显示

代表文件：
- `src/pet/window.py`

答辩讲法：
`pet` 是项目最核心的视觉交互层，负责让北极熊在桌面上真实动起来。

## 3. data 数据与成长模块

路径：`src/data/`

职责：
- 本地 JSON 存档
- 饱食度、心情、体力、好感度
- 等级、经验、金币、每日任务
- 背包、课程、日志等数据管理

代表文件：
- `src/data/store.py`

答辩讲法：
`data` 是项目的数据中心，负责所有状态持久化和成长机制计算。

## 4. features 功能页面模块

路径：`src/features/`

职责：
- 控制面板中的各个功能页
- 背包商店、聊天互动、成长等级、动作管理
- 课程提醒、系统设置、状态展示

代表文件：
- `src/features/backpack.py`
- `src/features/chat.py`
- `src/features/growth.py`
- `src/features/interaction.py`
- `src/features/notification.py`
- `src/features/settings.py`
- `src/features/status.py`

答辩讲法：
`features` 是用户可直接操作的功能集合，每个页面对应一个独立业务模块。

## 5. services 外部服务模块

路径：`src/services/`

职责：
- 大模型聊天接口封装
- 课程表图片 OCR 识别
- 第三方能力与本地功能之间的适配

代表文件：
- `src/services/llm_client.py`
- `src/services/course_ocr.py`

答辩讲法：
`services` 是项目的能力扩展层，把 AI 聊天和课程表识别这类外部能力封装成内部可调用服务。

## 兼容层说明

为了避免旧代码或旧文档中的导入路径失效，项目保留了少量兼容入口：

- `src/app.py` -> `src/core/app.py`
- `src/pet_window.py` -> `src/pet/window.py`
- `src/pet_data.py` -> `src/data/store.py`
- `src/course_ocr.py` -> `src/services/course_ocr.py`
- `src/llm_client.py` -> `src/services/llm_client.py`
- `src/modules/*.py` -> `src/features/*.py`

这些文件不再存放核心实现，只负责转发导入。答辩时可以说明：这是为了平滑重构，既保证结构清晰，也保证旧入口兼容。

## 模块依赖关系

```text
main.py
  |
  v
src/core/app.py
  |-- src/pet/window.py
  |-- src/data/store.py
  |-- src/features/*.py
  |-- src/services/llm_client.py

src/features/*.py
  |-- src/data/store.py
  |-- src/services/course_ocr.py
  |-- src/services/llm_client.py

src/data/store.py
  |-- src/services/llm_client.py
```

整体关系可以概括为：

```text
主控调度 core
    连接
桌宠表现 pet + 数据成长 data + 功能页面 features + 外部服务 services
```
